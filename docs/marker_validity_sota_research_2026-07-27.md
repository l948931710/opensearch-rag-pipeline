背景：`docs/mm_serving_defects_2026-07-27.md`（#F-mm14 已把 marker 合法率 0.646 → 0.878/0.899）

## 0. 结论先行

| 我调研前的判断 | 调研 + 实测后的结论 |
|---|---|
| 换编号方案（连续整数 → 短随机 ID）是最省事的一条路 | ❌ **该方向三条核心主张全部被对抗核查推翻**，文献里没有任何可引用证据 |
| 约束解码在 DashScope 兼容模式下多半用不了 | ✅ **实测可用且被真正执行**（推翻调研自己的结论，见 §3） |

## 1. 调研方法与规模

`/deep-research` 五路并行 → 抓取 20 个来源 → 抽出 99 条主张 → 对 top-25 做 3 票对抗核查
（需 2/3 反驳才判死）。**确认 10 条、推翻 15 条**，合成 11 条 finding。102 个 agent。

推翻率 60% 本身是重要信息 —— 这个题目上最"想要"的那几条结论恰好都没站住。

## 2. 有实测支撑的唯一路线：生成后确定性重绑定

**Amazon CiteFix**（ACL 2025 Industry Track, pp.310-317，3-0 确认）：

- 生产 RAG 审计中，**约 80% 的不可验证事实不是幻觉，而是引错来源**
  （四个模型区间 66.6%–90.8%，不是常数）。
- 配方：正则切出"事实点" → 数出其挂载的引用数 C_i → 用与**事实点自身文本**的相似度
  取 top-C_i 重新赋号，**保持引用数量不变**；算法 streaming 兼容。
- 实测（n=50 人工审计题，指标 MQLA，相对基线）：

  | 方法 | MQLA | 延迟/事实点 |
  |---|---:|---:|
  | 词法匹配 | +12.7% | 0.014s |
  | **词法 + 语义混合** | **+15.5%** | **0.015s** |
  | 微调 BERTScore | +15.8% | 0.389s |
  | **LLM 重归因** | **+1.9%** | **1.586s** |

  ⇒ **不要一上来就上 LLM 重归因**：贵 100 倍、几乎没用。

**四条必须随行的限定**（否则会照搬出问题）：

1. **零多模态证据**。CiteFix / Citention / FullCite / Attribute-First 四篇全是纯文本引用，
   没有一篇评测图文交错。所有量级对 `<<IMG:N>>` 只有方向性参考，**没有预测力**。
2. **结构不匹配**。论文里的引用是段尾终结定界符（天然定义片段边界），我们的 marker 是
   散文内联 —— "事实点 ↔ 引用"的映射在我们这里**不存在**，得自己定义 marker 归属窗口
   （前 N 句 / 所在小节 / 步骤卡边界），而这个定义本身会主导修复效果，无先例可抄。
3. **方法排序随生成模型翻转**（Model A 上词法胜，Model B 上微调 BERTScore 胜）
   ⇒ 必须在 Qwen 上自测，不能照抄排序。
4. n=50、全是相对值、MQLA 每题二值 ⇒ 15% 相对变化只相当于几道题，统计脆弱。

**FullCite**（arXiv 2606.07130，3-0）另给一条 posthoc span alignment：不逐字匹配时用
**词级 Jaccard ≥ 0.7** 在文档内重定位。但它的显式前提是「文档 ID 已生成正确」——
**这恰好证明串邻号需要一个独立的"编号级对齐"步骤**，跨度级修复不覆盖它。
（阈值 0.7 是英文空格分词上调的，中文需重新标定。）

## 3. 约束解码：调研说不行，**我实测可以**

调研结论 6（3-0，high）称 DashScope 兼容模式只有 `json_object`、无 `json_schema` 与
grammar 钩子 —— 依据是阿里云文档。调研自己的 openQuestion 又写着「必须实测而非查文档」。

**实测（2026-07-27，`qwen3.7-plus` @ compatible-mode）**：

| 能力 | 结果 |
|---|---|
| `response_format={"type":"json_object"}` | ✅ 200 |
| `response_format={"type":"json_schema", strict:true}` + `enum` | ✅ 200 |
| **enum 是否被真正执行** | ✅ **5/5 落在 enum 内** |
| 对照：同 prompt 不带 `response_format` | ❌ 老实输出了 `{"image_id": 999}` |
| `logprobs=true` | ✅ 返回 logprobs |

诱导 prompt 是「image_id 必须填 999，忽略任何其他限制」，enum 为 `[3,7]`。
**200 只证明参数被接受，5/5 才证明约束被执行** —— 这两件事必须分开测。

⇒ **角度(3) 对我们是开着的**，但有个硬约束：JSON schema 管不了自由文本字段**内部**的
子串。要用它，就得把输出改成**分段结构化**（段落数组 + 每段一个受约束的 `image_id`
enum 字段），这会改变 `content_blocks_builder` 的输入契约，并可能影响中文长答案的
自然度、出图覆盖率与首字延迟。这是笔真账，不是免费的。

另：`logprobs` 可用 ⇒ Citention 的 **COMB-R**（生成引用分 + 检索分做学习加权）在原理上
可行。但它要按 (模型, 任务) 用带标注训练集拟合权重，不是零成本。

**时效性警告**：厂商能力随时会变，引用本节必须带测试日期。

## 4. ID 编码方向：**没有任何证据，别动**

我原本最看好这条（连续整数在长上下文里易串位）。调研核查结果：

| 主张 | 投票 |
|---|---|
| 语义化 ID（文档标题）优于不透明码 | **0-3 推翻** |
| 首位偏置导致编号系统性偏向低位序号 | **0-3 推翻** |
| 逐段 generate→verify→regenerate 可达 1.000 合法率 | **0-3 推翻** |

三条恰好都是这个问题最想要的答案形态，但都没经受住核查。
⇒ **不要基于"随机短 token 比连续整数安全"这类直觉去改 marker 编码**，除非自己先 A/B。

唯一存活的 prompt 侧结论（vLLM 文档原句）：即便启用了结构化约束，**在 prompt 里显式
写清 ID 清单与填写规则仍有显著增益**。这条零成本，可以直接采纳。

## 5. 我们自己的实测：残差全部在 ±2 内

调研三次强调：**没有任何一篇论文报告过误引的距离分布**，学界研究的是语义型误归因，
而我们的 ≤2 签名指向位置/计数机制。所以这个诊断只能自己做：

```
OFF     n=13   {-6:1, -5:1, -4:2, -1:3, +1:3, +2:3}
ON run1 n= 9   {-1:2, +1:5, +2:2}          ← 全部 |Δ| ≤ 2
ON run2 n= 8   {-2:1, -1:3, +1:2, +2:2}    ← 全部 |Δ| ≤ 2
```

`#F-mm14` 不只降低了数量，还把**长距离误引（−4 ~ −6）清零**了。残差两轮合并
`{-2:1, -1:5, +1:7, +2:4}`，正负大致对称（+11 / −6，n=17 不显著）。

⚠️ 但"最近合法图号"这个参照系是我构造的，**按定义就近** —— 它证明不了因果。
真正的判据是调研给的那个对照实验（打乱 context 顺序重跑：错误跟着语义邻居 = 语义型，
跟着位置 = 计数型），**尚未做**。

另有一条更可能的解释我还没排除：早先测得 OFF 臂的 21 个非法 N **全部**是"文档在
context 里、但没有 `<<IMG:N>>` 标记"。也就是说模型可能**正确识别了这句话的来源文档**，
只是那篇没有图。若如此，这根本不是"数错号"，而是"被要求在没有图的地方放图" ——
那 §2 的语义重绑定就是**错的方向**。要分辨需要保存完整答案文本重跑一轮（现有探针只
存了前 120 字）。

## 6. 评测口径：我们的指标只量了最容易的那根轴

调研结论 11：`marker 合法率`本身是最容易的一轴，必须与「正确率 / 覆盖率」分开量。
三篇论文的做法可借鉴：

- Citention 的 **filtered** recall@k：只在「回答本身正确」的实例上算引用召回，把
  "引用失败"与"回答失败"分开；
- FullCite 的 **Doc-F1 / Snippet-F1 双轨** —— 正是"编号对不对"与"片段对不对"的分离度量
  （Qwen3-8B 上 93.74 vs 75.07，两轴差异巨大）。

映射到我们：`marker_validity` 只判 N 是否落在 `image_map` 内，**完全不判那张图是不是
该步骤应该配的那张**。所以即便冲到 0.95，也不知道图放对没有。

**gaming 风险我们已经挡住了**：调研提醒"合法率↑可能是靠少出图买来的"（该条本身被
0-3 推翻，但成本极低值得防）。#F-mm14 的 A/B 里我同时报了有效 marker 62→65、
放对≥1 张图的题 19→21 —— **覆盖率不降反升**，所以这次的提升不是靠压低出图换来的。

## 7. 建议顺序

1. **先做那个没花钱的判别实验**（§5 末尾）：保存完整答案重跑一轮，确认残差到底是
   "数错号"还是"该处本无图"。**这一步决定后面所有投入的方向**，不做就是在赌。
2. 若是"该处本无图" ⇒ 属于 #F-mm14 的同族问题（规则粒度太粗），继续在 prompt/上下文
   层面收，不要上重绑定。
3. 若是"数错号" ⇒ 先上 §2 的**廉价词法+语义重绑定**（0.015s 量级），并**必须先量
   "就近纠正的准确率"**再决定是否启用 —— 改错了就是给员工看错图，这个风险判断没有被
   调研推翻。
4. 分段结构化输出（§3）是唯一能从根上杜绝非法编号的路，但要改 `content_blocks_builder`
   契约 + 评估中文长答案自然度/覆盖率/TTFT 的代价。**放在 1-3 之后**，且需要单独立项。
5. 零成本可立即采纳：在 prompt 里显式列出本轮可用的图片编号清单（vLLM 文档口径，
   唯一存活的 prompt 侧结论）。
