## 疑似方向(请贵方核实)

丢失窗口与 pushDocuments 全量超时窗口重合,我们怀疑 07-16 傍晚(北京 17:00–23:30)实例发生了服务端事件(增量 merge / generation 构建切换 / failover / 节点重启),该事件:①占死写入路径导致超时;②切换过程中丢弃了部分已确认写入的存量行。

两点背景供参考:
- 本表为 Swift 实时推送、`autoBuildIndex=false`、无持久离线全量源——若周期性 merge/generation 切换依赖 Swift log 回放,而部分行的 log 段已过保留期,是否会造成这种"散布单行丢失"?(我们此前已因此踩过一次"全量重建回放过期 Swift log → 空 generation 上线"的检索中断,深知此拓扑敏感。)
- 2026-06-07 前后我们在同实例上创建的多张测试表(`*_v2/v3/v4`)全部卡在 `building`(errorCode 3000 `init gig stream failed`)且无法删除(IndexInUse)——不确定是否与 build 链路资源竞争相关,一并提供线索。
