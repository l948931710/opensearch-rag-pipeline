你是本轮 UI/UX 设计迭代的 **调度器兼实现者**。严格按下列顺序执行,**完成候选比较前不得改任何代码**。实现由你(主会话)完成;审计与评审必须委派给独立 subagent,以保证评审从未看过你的实现推理。委派时**不要传 model 覆盖**——auditor/reviewer 的模型钉在各自 agent 定义里,实现/审计/评审三角有意异模型(防同源盲区与自评偏好)。

$ARGUMENTS

> **审美意图的定位**:它是一条方向性描述(如「信息密度更接近 Linear 的克制感」),用来引导探索与实现的取舍、并要求 auditor/reviewer 做前后对比截图。它**不是验收条件**——不参与硬门判定,也不计入 KEEP/REVERT。审美是否真的达到,由你看截图后自行判断。

## 流程(单次最多内循环 3 轮)

1. **审计** — 用 Task 委派 `ui-auditor`,传入上面的任务输入,并附上 `docs/ui_iterate_redlines.md`(红线/WONTFIX 登记表)的路径。拿回基线度量快照与高价值问题。先记录当前 git 基线 commit,确认工作区干净,不覆盖未提交改动。

2. **探索与决策**(按复杂度触发,不强制套数):
   - 优先复用项目内 code 已有的 token、组件、交互模式(code 是 source of truth)。
   - 不够时再参考外部成熟后台体系的**模式**(Carbon / Fluent / Atlassian / Spectrum / Linear / Stripe 等),经 web search、browser use 实地看、或读你有权限的官方设计系统 Figma 库——只提模式,不搬品牌色/字体/商标/插画/完整页面,守授权。
   - 若本轮提供了**审美意图**,作为候选方案取舍的参考方向之一,与功能性目标并列写进候选对比;但**审美偏好不得作为突破第 3 步实现约束或第 7 节硬指标的理由**。
   - 简单修复:1 方案 + 1 对照。结构或流程性改动:≥2 来源、2~3 候选。每候选写明 `目标问题/来源/层级变化/任务路径变化/交互模式/实现范围/风险/验收标准/与审美意图的契合度(若有)`,选改动可控的平衡方案。

3. **实现**(受限):只处理本轮一个主题,最多改 5 个主要文件。**禁止**改 API 契约 / 权限判断 / 业务状态机 / 数据库结构,禁止加大型依赖,禁止为减步数绕过必要确认或权限,禁止更新视觉基线掩盖变化。允许:调布局/层级/密度、统一状态与交互、补齐 loading/empty/error、补返回/撤销/恢复路径、给异步操作加反馈、为破坏性操作加确认。记录改了哪些文件、对应哪条决策、受影响的任务路径、需重点验证的场景。

4. **验证(硬门)**:运行**脚本化 Playwright**,用与基线相同的数据、视口、操作路径,覆盖本轮改动相关的状态。pass/fail 只由脚本判定,不靠自由浏览。任一硬指标失败即视为本轮未通过。**硬门断言必须逐条落实第 1 步 auditor 给出的验收条件**(断言↔验收条件的对应关系写进改动记录),不得自拟更弱的断言替代;KEEP 后本轮断言沉淀进 console-app 常驻 e2e 套件(`console-app/tests/`),不留在 scratchpad 里失传。

5. **评审** — 用 Task 委派 `ux-reviewer`,传入基线度量快照、你的改动说明、Playwright 结果与截图。读取它返回的 `VERDICT:` 行。

6. **按裁决行事**:
   - `KEEP` → 只提交本轮相关文件,独立 commit,message 写明设计目标(如 `ux(documents): keep form data on validation error`)。若本轮出现新的用户拍板(WONTFIX / 证伪的审计结论 / 口径约束),同步追加进 `docs/ui_iterate_redlines.md`(注明日期)。结束本轮。
   - `ITERATE` → 在同一设计目标下做最小修正,回到第 3 步(本命令内最多 3 轮)。
   - `REVERT` → `git` 回退本轮改动到基线 commit,不留半成品,记录原因。
   - `STOP` → 停止并记录原因。

## 环境与硬门地雷(console-app 实战沉淀,写脚本前先读)

- **E2E 进入点用 `/console/?token=<任意串>` + mock `/api/kb/whoami`,绝不能用 `?preview`**:preview 注入的 token 会让 `lib/api.ts::apiFetch` 把所有 authed 请求合成 503 直接短路、根本不 fetch,`page.route` 全部截不到、mock 全失效。两者都不需要真后端。
- **先核端口再跑门**:主仓 vite 常驻 :5173,worktree 里 `npm run dev` 会**静默落到 :5174**;先 `lsof -iTCP:5173` 核对,e2e 显式带 `BASE_URL=` 跑,否则打到旧代码假绿。
- **自己的 route mock 必须注册在 installRoutes 之后**(Playwright 后注册者优先);复用 fixtures 时字段严格对齐 `useKb.ts`。
- **e2e 不与 vitest / 双 dev server 并发跑**(已证实的超时 flake 源);硬门红了先隔离复跑再定性。
- **fixture/mock 里的日期一律相对 `Date.now()`**,硬编码日期会腐坏(agent-approvals `expires_at` 过期事故)。
- **Playwright 断言词不得出现在你输入的问句里**:问句会成为侧栏会话标题 + 删除按钮的可读名,`getByRole` strict-mode 多命中。
- SSE mock 帧格式对齐 `lib/sseDecoder.ts`:`data: <json>\n\n` 每帧 + `data: [DONE]\n\n` 结尾。

## 停止条件(任一即停)

硬指标全过且目标达成 / 满 3 轮 / 连续两轮无可证明改善 / 改动增加复杂度却不提升任务效率 / 找不到更优方案 / 出现不可接受的业务回归风险。**禁止无限迭代。**

## 最终输出

本轮目标 → 基线问题 → 探索与候选(含与审美意图的契合度,若有)→ 实现改动 → 验证结果 → 指标前后对比(含端到端步数/切换/滚动/首屏)→ **审美变化(前后截图对比,仅供参考,不计入裁决)** → 裁决与依据 → 遗留问题与「待人判断」项。
